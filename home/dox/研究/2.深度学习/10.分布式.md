# 1. 为什么需要分布式训练

## 1.1 计算、显存与通信瓶颈

单卡瓶颈可能是参数与状态放不下、激活占满显存、计算太慢或数据供给不足。不同并行方法解决不同瓶颈：数据并行扩大吞吐，状态分片减少冗余，模型并行分担单个模型的计算与存储。

先建立单卡账本：参数、梯度、优化器状态、激活、临时缓冲分别占多少。增加 GPU 不会自动加速数据读取，也不能消除串行依赖；通信和同步反而可能成为新瓶颈。

## 1.2 全局 batch 与实验语义

等大小微批次下，全局 batch=每卡 batch×数据并行卡数×梯度累积步数。张量并行卡数不应再乘进数据 batch，因为它们共同处理同一份样本。

改变全局 batch 会改变梯度噪声和更新次数。扩展实验要区分固定 batch 的强扩展与随设备数增加 batch 的弱扩展，并说明是否调整学习率和训练步数。

# 2. 数据并行

## 2.1 副本、梯度平均与 DDP

DDP 为各设备保留模型副本，各自处理不同数据，再同步梯度，使相同初值和优化器状态的副本获得一致更新。

![两张卡的数据与梯度流](/dist-ddp.png)

图中的平均梯度对应各卡等权；若每卡有效 token 数不同，直接平均各卡局部均值可能产生权重偏差。应按全局有效样本或 token 数归一化。采样器还需避免所有卡反复看到同一份数据。

## 2.2 梯度累积与同步时机

累积期间可延后部分同步，最后一个微批次再进行集合通信，从而减少通信频率。但必须保证所有设备按照兼容顺序进入同步操作，否则可能死锁。

累积不自动解决激活显存，因为每个微批次仍需完成前向反向；它主要模拟更大有效 batch。异常跳步、梯度缩放和条件分支应在各设备之间保持一致语义。

# 3. 集合通信

## 3.1 All-Reduce、All-Gather 与 Reduce-Scatter

All-Reduce 将各设备张量逐元素规约，并把结果返回所有设备；All-Gather 收集分片组成完整张量；Reduce-Scatter 先规约再将结果分片分发。

![三种集合通信的数据结果](/dist-collectives.png)

图中 Reduce-Scatter 的每张卡只得到和的一部分，而 All-Reduce 得到完整和。很多训练算法可用这些基本操作组合；理解张量在操作前后的所有权，比记忆 API 名字更重要。

## 3.2 带宽、延迟与通信重叠

小消息常受延迟限制，大消息常受带宽限制。梯度桶把多个小张量合并通信，并尝试与反向计算重叠；桶过大延迟启动，过小增加调度成本。

重叠只有在计算和通信能够并行且不争用关键资源时才有效。跨节点网络、GPU 拓扑和进程放置都会改变结果；应使用时间线分析实际空闲，而不是仅凭理论带宽估算。

# 4. 状态分片

## 4.1 ZeRO 与优化器状态分片

ZeRO 逐步分片优化器状态、梯度和参数，消除数据并行副本中的冗余。不同阶段节省的显存不同，带来的通信和参数可用时机也不同。

![ZeRO 各阶段分片对象](/dist-sharding.png)

图中 P、G、O 分别表示参数、梯度和优化器状态。分片不会消除激活，也不会把所有峰值显存严格除以卡数；临时聚合、缓冲和未分片状态仍需计入。[ZeRO 论文](https://arxiv.org/abs/1910.02054)。

## 4.2 FSDP 与参数按需聚合

FSDP 在需要计算某个模块时聚合参数，计算后可重新分片，并对梯度执行相应规约。包装边界、预取与保留策略影响峰值显存和通信频率。

模块包得太大可能造成聚合峰值过高，太细又增加通信开销。检查点可以是完整或分片形式，恢复到不同设备数时要使用匹配的保存加载流程。参见 [PyTorch FSDP 文档](https://docs.pytorch.org/docs/stable/fsdp.html)。

# 5. 模型并行

## 5.1 张量并行与流水线并行

张量并行把单个矩阵或算子的维度拆到多卡，层间常需通信；流水线并行把不同层放在不同阶段，通过微批次填充流水线。

![数据、张量、流水线与专家并行](/dist-parallel.png)

图中四种方法切分的对象不同。流水线还面临填充和排空的空闲气泡；划分时应平衡实际计算与激活传输，而不是机械地给每张卡相同层数。

## 5.2 上下文并行与专家并行

上下文并行把长序列沿位置分布到多设备，需要交换注意力所需信息；专家并行把 MoE 专家分散，并根据路由发送 token。

专家热门程度不均会让部分设备拥塞，通信量也随路由变化。多维并行可以组合，但每增加一种切分都会增加调度、检查点和故障恢复复杂度，应从明确瓶颈出发。

# 6. 可靠训练

## 6.1 检查点、采样器与恢复

恢复训练不仅恢复权重，还应处理优化器分片、调度器、采样器、随机状态和训练进度。所有设备应对保存步数达成一致，避免混合不同时间的分片。

检查点写入先完成临时文件，再发布完整标记或原子替换，防止把部分写入当成可恢复快照。至少实际执行一次中断恢复实验，并比较损失、样本顺序和下一步更新是否符合预期。

## 6.2 混合精度与数值一致性

浮点加法不满足结合律，改变设备数、规约树或混合精度可能产生小差异，长期训练后可以扩大。逐位一致与统计可复现是不同目标。

梯度溢出时各卡应一致跳过更新；损失缩放和裁剪顺序要明确。报告软件版本、通信后端、dtype 与确定性设置，才能区分正常数值差异和真正的训练错误。

# 7. 大模型系统进展

## 7.1 MoE 路由、负载均衡与 DualPipe

MoE 将路由、专家计算和跨设备通信紧密耦合，负载均衡影响吞吐与模型质量。DeepSeek-V3 报告中的 DualPipe 等设计尝试重叠计算与通信，效果依赖具体拓扑和工作负载。[技术报告](https://arxiv.org/abs/2412.19437)。

![流水线微批次与空闲气泡](/dist-schedule.png)

图展示最基本的填充与排空，不代表 DualPipe 的完整调度。理解简单时间线后，再比较复杂方案减少了哪些空闲、增加了哪些缓存和依赖。

## 7.2 吞吐、MFU 与扩展效率

吞吐应按有效样本或有效 token 计数，排除 padding 的口径要明确。MFU 用模型计算需求与硬件峰值作比较，其计算约定必须说明；高 MFU 不等于任务质量更高。

强扩展效率可写为 $E_N=T_1/(NT_N)$，前提是比较相同工作量。给出端到端时间、数据等待、通信占比、检查点成本和达到目标质量的总成本，才能判断分布式方案是否真正值得。

## 综合算例：全局 batch 与平均梯度

四张数据并行卡，每卡微批次 8，累积 4 次，则全局 batch 为 128。若还有两路张量并行组成每个模型副本，这两路共同处理同一微批次，不会把全局 batch 再翻倍。

各卡样本数相同时，先求局部平均再平均等价于全局平均；若一张卡只有一半有效 token，应使用相应权重。训练能跑通并不代表梯度等价，最好在无随机层的小模型上与单卡全局批次进行数值对照。

## 显存预算与扩展实验

混合精度 Adam 的常见配置可能同时包含低精度参数、梯度、FP32 主副本及两个矩状态；具体每参数字节数依实现而定。先按实际 dtype 逐项核算，再加激活和通信临时峰值。用 1、2、4 卡测相同工作量，观察时间线中通信与空闲占比如何变化。
