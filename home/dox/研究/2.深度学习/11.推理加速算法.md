> 本篇沿用《动手学深度学习》的学习顺序，以原创图解、推导和工程实例整理。扩展研究核对至 2026-09-21；示意图不代表实测结果。

# 1. 先定位瓶颈

## 1.1 Prefill 与 Decode

Prefill 处理已知输入上下文，可以并行计算多个位置；Decode 每次生成新 token，存在自回归依赖。长输入通常增加首 token 等待，长输出增加持续生成成本。

![输入处理与逐 token 生成](/infer-prefill.png)

图中 TTFT 是请求开始到首 token 的时间，TPOT 描述后续 token 间隔。短输入、长输入、小并发和大并发的瓶颈不同，不能用一个“tokens/s”概括所有体验。

## 1.2 时延、吞吐、显存与服务目标

首先确定服务目标：首 token 延迟、每 token 延迟、端到端延迟、吞吐、峰值显存及质量。平均值之外应观察 p95、p99；队列拥塞可能让尾延迟迅速恶化。

![算术强度与 Roofline 瓶颈](/infer-roofline.png)

图是概念模型：算术强度低时易受带宽限制，高时可能接近计算上限。真实系统还受内核启动、通信和调度限制。诊断时分别测模型计算、分词、排队和网络发送，避免优化错误环节。

# 2. 算子与编译优化

## 2.1 融合、图捕获与 torch.compile

算子融合减少中间结果写回和内核启动；图捕获减少重复提交开销；编译可进行布局和算子层面的优化。收益取决于形状稳定性、算子支持和批量大小。

预热、编译时间与稳态测量分开。固定形状的最佳表现不代表变长服务；应覆盖实际长度分布，记录重编译、缓存命中和异常回退。数值一致性需在优化前后验证。

## 2.2 FlashAttention 与硬件协同

FlashAttention 通过分块和在线归一化减少注意力中的显存读写，不改变为稀疏注意力。小 batch decode 与大规模 prefill 的形状不同，最佳内核也可能不同。

内核选择要结合 GPU 架构、精度、head dimension 和掩码。端到端速度由最慢环节决定：注意力快一倍，不意味着整个模型快一倍，FFN、权重读取与调度仍可能占主要时间。

# 3. KV cache 管理

## 3.1 缓存规模、GQA 与 MLA

普通 KV cache 的近似字节数为 $M=2BLTH_{kv}d_hs$，B 为序列数，L 为层数，T 为缓存长度，$H_{kv}$ 为 KV 头数，$d_h$ 为头维，s 为每元素字节数；2 对应 K 和 V。

例如 B=1、L=32、T=8192、$H_{kv}=8$、$d_h=128$、s=2，约为 1 GiB。它不包含权重、激活和管理开销。GQA 减少 KV 头，MLA 使用不同压缩表示，后者不能直接套同一公式。

## 3.2 PagedAttention、前缀复用与驱逐

PagedAttention 用块表把逻辑连续的 token 缓存映射到不必物理连续的显存块，减少动态长度引起的碎片，并支持某些前缀共享。

![逻辑 token 块与物理缓存块](/infer-kv.png)

图中共享前缀可指向同一只读块，后续分叉需要正确管理写入。它不消除 KV 本身的容量需求；驱逐后再次访问可能需要重算或传回。缓存键还应包含模型版本和影响计算的配置。[原论文](https://arxiv.org/abs/2309.06180)。

# 4. 量化

## 4.1 对称、非对称与分组尺度

仿射量化可写为 $q=\operatorname{clip}(\operatorname{round}(x/s)+z)$，重建 $\hat x=s(q-z)$。s 控制步距，z 对齐零点，超出范围的值被截断。

![浮点值映射到整数网格](/infer-quant.png)

图中舍入误差与截断误差来源不同。逐张量尺度成本低，逐通道或分组尺度更灵活但增加元数据和计算。量化位宽相同，不同分组与异常值处理也可能有很大质量差别。

## 4.2 PTQ、QAT、GPTQ 与 AWQ

PTQ 在训练后利用校准数据确定量化配置；QAT 在训练中模拟量化误差以适配模型。GPTQ 利用近似二阶信息处理权重量化，AWQ 关注激活相关的权重重要性；它们并不是对所有模型都同等有效。

权重量化、激活量化和 KV 量化解决不同内存与带宽问题。校准数据应覆盖实际输入长度、语言和任务，不能只用少量容易文本。参见 [GPTQ](https://arxiv.org/abs/2210.17323)、[AWQ](https://arxiv.org/abs/2306.00978)。

## 4.3 FP8／FP4 与精度验证

FP8、FP4 属于低精度浮点表示家族，具体格式、缩放粒度和硬件支持会影响结果。低位数不自动意味着低延迟：若频繁反量化或缺少高效内核，收益可能被抵消。

验收不仅看平均困惑度，还应检查数值推理、长上下文、罕见 token、结构化输出和任务尾部失败。比较时明确哪些张量被量化、哪些保留高精度，以及显存统计是否包含量化元数据。

# 5. 调度与解码

## 5.1 连续批处理与分块 Prefill

连续批处理在请求完成后及时插入新请求，减少静态 batch 中等待最慢样本的浪费。分块 prefill 将长输入拆成调度片段，缓解它对正在 decode 请求的阻塞。

二者改善资源利用，也带来公平性和排队取舍。调度器需要平衡吞吐与延迟目标；无限增大 batch 可能提高总吞吐，却让单个用户等待更久。

## 5.2 推测解码与精确接受规则

草稿模型先提出多个 token，目标模型并行计算这些位置的条件概率。对草稿分布 q 提出的 token x，精确采样可按 $\min(1,p(x)/q(x))$ 接受；首次拒绝后从归一化的 $\max(0,p-q)$ 残差分布采样，并丢弃后续草稿。

![接受前缀、首次拒绝与修正采样](/infer-speculative.png)

图中不能简单把“目标 argmax 相同”当作所有采样设置的接受规则。收益取决于接受率、草稿成本和验证批量；正确算法保持目标采样分布，而非保证随机种子下逐字相同。[推测解码论文](https://arxiv.org/abs/2211.17192)。

# 6. 模型压缩

## 6.1 蒸馏、剪枝与结构化稀疏

蒸馏用教师的输出或中间表示指导学生，压缩模型同时改变其能力边界；剪枝删除权重、通道或层。非结构化稀疏只有被硬件与内核利用，才可能带来明显时延收益。

结构化剪枝更容易减少实际运算，但可能损失关键表示能力。压缩后需重新评估校准、长尾任务和部署稳定性；只报告压缩率而不报告质量与速度，无法判断实用价值。

# 7. 实验与最新进展

## 7.1 FlashAttention-4 与系统协同

2026 年 FlashAttention-4 将算法与内核流水线共同设计，针对特定新硬件中计算、带宽和特殊函数吞吐增长不一致的问题。其优化包含更细致的数据搬运与执行重叠，不能理解为所有设备都能直接获得相同收益。[FA4 论文](https://arxiv.org/abs/2603.05451)。

更大的系统收益往往来自内核、量化、缓存和调度共同配置。组合优化前先验证单项正确性，再测组合效果，因为缓存布局和量化格式可能互相限制。

## 7.2 可复现的压测与质量回归

压测使用实际输入／输出长度分布和到达率，区分冷启动、预热与稳态。记录请求失败、截断和超时；忽略失败请求会夸大吞吐与质量。

| 维度 | 至少记录 | 解释 |
| --- | --- | --- |
| 工作负载 | 长度分布、并发、到达率 | 决定瓶颈 |
| 硬件软件 | GPU、版本、dtype | 决定可复现性 |
| 时延 | TTFT、TPOT、p95 | 决定用户体验 |
| 资源 | 峰值显存、吞吐 | 决定部署规模 |
| 质量 | 任务指标、失败切片 | 防止以质量换速度 |

最终比较“在质量和延迟约束下可服务多少请求”，而不是孤立追求一个最高速度数字。

## 综合算例：量化误差

假设对称有符号整数范围为 [-127,127]，校准最大绝对值为 1.27，则尺度 s=0.01、零点 z=0。x=0.234 被量化为 23，重建为 0.23，舍入误差为 -0.004；x=2 超出范围，重建只能到 1.27，截断误差明显更大。

因此少量异常值会迫使尺度变粗，或者在截断时承受较大误差。分组尺度、异常值通道处理和校准覆盖度都可能改变结果，位宽不是唯一变量。

## 组合优化的验收顺序

先建立未优化基线，再分别验证量化、缓存、内核和调度，最后组合。精确优化应检查数值容差与采样语义；有损压缩应检查任务质量。相同输入、输出上限、并发与硬件下测量，另保留代表实际业务分布的端到端压测。
