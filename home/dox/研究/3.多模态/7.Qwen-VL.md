# Qwen-VL：动态视觉、视频与多模态推理

> 原创机制图解；架构示意不替代具体版本配置，算例不是实测成绩。资料核对：2026-09-22。

## 1. 系列版本与阅读方法

![系列版本与阅读方法](/qwen-roadmap.png)

### 1.1 按机制阅读系列

Qwen-VL 是视觉语言模型系列，不同代际涉及视觉分辨率、位置编码、视频处理和跨层融合等变化。原始 Qwen-VL、Qwen2-VL、Qwen2.5-VL 与 Qwen3-VL 应分别对应论文、代码和检查点，不宜把后一代功能反推到前一代。

图中四张版本卡只是阅读索引。比较性能时需同时记录参数规模、Dense/MoE、Instruct/Thinking、输入预算和生成设置，系列名称本身不足以确定运行条件。

### 1.2 配置与能力范围

同一代模型也可能有不同规模与任务变体。生成模型输出文本，Embedding 输出向量，Reranker 输出相关性分数；它们共享研究背景，但不能使用同一解码和评估流程。

## 2. 动态分辨率与视觉预算

![动态分辨率与视觉预算](/qwen-resolution.png)

### 2.1 动态视觉表示

动态分辨率让不同尺寸和宽高比的图像获得不同视觉位置预算，减少把所有图像压成同一小正方形造成的信息损失。实际预处理仍受到最小/最大像素、patch 与合并规则约束，并非任意尺寸都原样送入模型。

图中 token 数随图像内容承载的空间网格变化。应从 processor 输出和模型配置确认真实数量，不用一个跨版本固定常数估算所有输入。

### 2.2 预算与任务

文档小字、细线图表和远处小物体可能需要更高分辨率；大物体识别可能并不受益。按任务设置预算，比无条件使用最大分辨率更可控。

增加视觉 token 会占用语言上下文与 KV 缓存，影响首字延迟和并发。评估应报告图像尺寸、处理后预算与质量变化，避免只展示最佳样例。

### 2.3 用公式核对预算

若处理后空间网格为 $H_g\times W_g$，每 $m\times m$ 个空间位置合并为一个语言侧视觉 token，在网格可整除且忽略特殊标记时，教学估算为 $N_v=H_gW_g/m^2$。这不是跨版本固定公式：视频还涉及时间 patch、抽帧和特殊标记，应以 processor 的真实输出为准。

对已知每帧产生 $n_f$ 个视觉 token 的简化视频输入，$N_{video}\approx F n_f$；图像尺寸已经通过 $n_f$ 体现，不能再乘一次像素面积。若每帧 256 个 token、抽取 16 帧，则视觉部分约 4096 个 token，还需给文本和回答留出上下文空间。固定架构与 KV 精度时，缓存容量通常随序列长度近似线性增长，注意力计算则不能统一视为线性。

## 3. 位置、视频与时序对齐

![位置、视频与时序对齐](/qwen-position.png)

### 3.1 空间与时间需要不同位置含义

文本具有序列位置，图像具有高宽网格，视频还具有时间。Qwen 系列使用并演进多模态位置表示以处理这些结构；具体位置编码与时间对齐方案随版本变化。

图中三轴表示信息维度，而不是声称所有模型直接把三个整数相加。帧索引、采样时间和真实时间戳必须区分，尤其是变帧率或非均匀抽帧。

### 3.2 时序诊断

对视频问“先发生什么”和“物体现在在哪里”使用的证据不同。可以反转帧顺序、减少采样或删除关键帧，检查答案是否相应变化。若答案完全依赖单帧语义，长视频上下文并没有被真正利用。

位置输出还需还原到原图坐标。缩放、补边、切片和归一化的逆变换应有明确实现，不能只看文本框格式是否正确。

## 4. Processor、消息与生成

![Processor、消息与生成](/qwen-api.png)

### 4.1 配套处理器是模型接口的一部分

采用官方消息结构描述图像、视频和文本，由配套 AutoProcessor 处理模板及视觉输入，再调用对应模型类。图中 input_ids、attention_mask、pixel_values 只是典型字段，具体模型还可能要求网格与时间信息。

不要手工删除自己不认识的 processor 字段；也不要把所有张量统一转换为浮点，token 索引与网格可能需要整数。设备移动和 dtype 转换是两个不同操作。

### 4.2 解码与批处理

decoder-only 生成通常返回输入前缀加新增 token，解码时按实际输入宽度裁出新增部分。padding 方向、图像顺序与多轮模板必须与模型要求一致。把原始问题也解码出来会污染结果和评分。

记录 model_id 与 revision，固定 processor 和生成参数。官方示例的最低库版本是加载条件，不代表用户本地环境已经满足；先做一张本地图的最小推理，再扩展视频与批量。

## 5. Qwen3-VL 与多模态检索

![Qwen3-VL 与多模态检索](/qwen-retrieval.png)

### 5.1 Qwen3-VL 的研究方向

Qwen3-VL 扩展视觉语言融合与多模态位置处理，并提供多种规模及指令/推理变体。阅读其技术报告时，应将结构变化、数据变化和推理预算分开，避免把整体效果解释成某一个模块的收益。

生成式推理可以提供较长分析，但长输出并不自动更准确；应检查最终答案、关键视觉事实和成本。对于看不清的内容，需要评估信息不足时的行为。

### 5.2 2026 年多模态检索扩展

Qwen3-VL-Embedding 与 Qwen3-VL-Reranker 将系列能力用于多模态召回和重排。典型系统先用向量检索少量候选，再用更细的相关性模型重排；生成回答可作为后续独立环节。

图中三个接口承担不同职责。检索评估关注 Recall@K、排序质量与图库规模，生成评估关注答案与证据，不能把两者分数混为一谈。

## 6. 算例与实践

### 6.1 检索级联算例

假设图库有十万项，向量召回 100 项，再重排前 20 项供阅读。若正确项不在召回的 100 项中，重排无法补救；因此应分别测召回覆盖和重排质量。100、20 是教学预算，不是推荐默认值。

### 6.2 输入合同自检

保存一张非正方形图的原尺寸、处理后尺寸和输出网格；询问同一可见对象的名称与坐标。核查坐标是否对应原图，再加入第二张图检查指代。视频测试增加时间戳核对。每次只改变一个条件，便于区分处理器错误和模型能力不足。
