# 面向视觉的语言模型：接口与条件生成

> 原创机制图解；架构示意不替代具体版本配置，算例不是实测成绩。资料核对：2026-09-22。

## 1. 视觉与语言的连接器

![视觉与语言的连接器](/visual-connector.png)

### 1.1 两种接口问题

视觉编码器输出 $V\in\mathbb R^{N_v\times d_v}$，语言模型使用 dₗ 维表示。线性投影 $H=VW$，$W\in\mathbb R^{d_v\times d_l}$ 解决维度不匹配，输出仍有 Nᵥ 个位置；查询压缩则把 Nᵥ 个位置聚合为 M 个，解决 token 数量问题。

图中两条路线强调“维度”和“数量”是独立选择。MLP 能增加非线性映射，却不会凭空恢复视觉骨干已经丢弃的文字或位置。

### 1.2 连接器不是全部能力

连接器参数少可能降低训练成本，但端到端性能还受视觉表征、语言骨干、数据和训练策略影响。公平消融应只改连接器并控制其余条件，而不是比较两个完整系统后把所有收益归给这一模块。

## 2. 视觉 token 与注意力掩码

![视觉 token 与注意力掩码](/visual-mask.png)

### 2.1 前缀与生成位置

语言模型接收图像表示、用户文字和对话模板，按条件概率逐 token 生成回答。因果掩码阻止回答读取未来答案；图像位置之间是否双向可见、是否使用交叉注意力，依模型架构而定，不能套用同一张通用掩码。

图中视觉前缀是信息输入，图像占位符是模板中的标记，两者不是同一物体。processor 可能把一个占位符展开为多个视觉位置；手工计算占位符数而忽略处理器规则，会产生长度错配。

### 2.2 位置和 padding

padding mask 排除补齐位置，causal mask 排除未来依赖，两者可以同时存在。多图顺序、图像边界和视频时间需要在输入表示中保留；只有像素张量而没有对应模板，模型可能无法建立正确指代。

## 3. 对齐、指令微调与标签

![对齐、指令微调与标签](/visual-training.png)

### 3.1 对齐与指令学习

先对齐视觉接口，再使用问答或多轮指令训练，是一种常见路线；有些系统采用联合训练或其他阶段安排。冻结哪些模块、使用什么目标、是否加入纯文本数据都应按具体版本记录。

生成监督可写为 $L=-\sum_t m_t\log p(y_t\mid I,q,y_{<t})/\sum_t m_t$，m 是损失掩码。只监督回答是一种常见设置，输入问题仍可被注意力读取。

### 3.2 三类掩码不能互换

labels=-100 通常表示该位置不计交叉熵，不表示该 token 对其他位置不可见。训练框架可能在模型内部移动标签以实现下一词预测；再次手工移动会造成双重错位。

图中问题、图像和 padding 的监督规则必须写清。批量训练若把补齐位置当作目标，模型可能学会过早结束或重复输出。

## 4. 坐标、视频与上下文预算

![坐标、视频与上下文预算](/visual-budget.png)

### 4.1 坐标输出需要几何合同

模型输出框可以是像素坐标、归一化浮点或离散整数。必须声明原图尺寸、处理尺寸、坐标顺序和闭开区间。输出看起来像四个数，不代表对应正确图像空间。

视频多一个时间轴。抽帧索引、实际时间戳、变帧率与采样间隔应分开记录；将第 10 帧误读成第 10 秒会让事件定位完全错误。

### 4.2 上下文预算

粗略地，视频视觉预算随帧数与每帧视觉 token 的乘积增长，但空间合并、时间压缩和动态切片会改变实际值。图中预算只是记账框架，最终应从 processor 的输出读取真实 shape。

输入上下文和输出 token 共享模型容量限制。长视频或多页文档可能挤占回答空间；截断策略需要保留与问题相关的证据，而不能无声丢弃尾部。

## 5. 推理接口与可验证回答

![推理接口与可验证回答](/visual-inference.png)

### 5.1 从消息到张量

通常使用模型配套 processor 统一处理聊天模板、文本 token、图像尺寸和像素张量，再将模型所需字段传给 generate。AutoModelForCausalLM 面向文本生成，视觉模型可能使用专门类或 AutoModelForImageTextToText；应以模型文档支持为准。

图中解码只取新增 token。对 decoder-only 模型，generate 的序列通常包含输入前缀；encoder-decoder 的返回约定不同，不能套同一裁切逻辑。

### 5.2 可验证输出

要求回答同时给出图中可见依据、单位或位置，有助于检查，但模型编写的“依据”仍可能错误。应由原图、标注或独立程序核验。对于不可见细节，正确行为可能是说明信息不足。

运行记录保存模型 revision、processor、库版本、视觉预算和生成参数。随机采样的重复试验与确定解码回答的是不同问题。

## 6. 算例与实践

### 6.1 连接器的形状算例

假设 Nᵥ=256、dᵥ=1024、dₗ=4096，线性投影权重含 4,194,304 个参数，偏置另计；输出仍是 256×4096。如果压缩到 32 个查询，输出数量减少八倍，但是否保留小字信息需要实验，而不是仅按压缩率推断。

### 6.2 掩码自检

构造一个问题和两个回答 token 的小批次，打印 input_ids、attention_mask、labels 三列。检查问题是否可见而不计损失、padding 是否被屏蔽，以及目标是否只错位一次。随后加入第二张图，核查模板与像素批次顺序。
