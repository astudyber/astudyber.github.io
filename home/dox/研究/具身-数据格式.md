# <font color='#2aa198'>数据格式</font>：让每条轨迹可解释、可迁移
## 1. 轨迹基本字段
每条 episode 至少包含时间戳、图像或视频帧、机器人状态、动作、语言指令、任务标识、终止原因和成功标签。多传感器数据必须保存采样频率、坐标系、内外参和单位，不能只依赖文件名猜测含义。

## 2. 常用组织
可用 JSON 元数据加 PNG/MP4 文件，或使用 HDF5、Zarr、LeRobot 等分片格式。大规模训练时按 episode 分片并建立索引，避免每次扫描整个目录。图像、状态和动作应通过同一时间轴关联，而不是依赖数组下标碰巧对齐。

## 3. 推荐元数据
保存 `episode_id`、`robot_id`、`task_id`、`camera_serial`、`calibration_version`、`fps`、`action_space`、`success`、`failure_reason` 和 `dataset_version`，使单条轨迹能够独立解释。若存在人工接管，还应保存接管起止时间和原因。

## 4. 校验规则
检查字段完整性、时间单调性、图像可读性、动作范围、NaN、重复轨迹和标签一致性；格式转换后随机抽样可视化回放。对每次校验生成报告，统计缺失率、异常率和被剔除 episode 列表。

## 5. 版本兼容
格式升级时保留 schema 版本和迁移脚本，禁止直接覆盖原始数据。对字段重命名、单位变化和坐标系变化提供向后兼容说明，确保旧模型仍能复现实验结果。
