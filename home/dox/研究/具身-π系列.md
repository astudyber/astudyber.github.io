# π 系列：通用机器人策略的工程化阅读
## 1. 问题定义
<font color='#d33682'>π 系列</font>可以理解为一条从视觉语言预训练走向真实动作执行的路线。它要解决的不是单个抓取器，而是“同一个策略如何理解不同指令、面对不同物体，并在不同机器人上稳定执行”。输入包含多视角图像、机器人本体状态、语言指令和历史动作，输出则是末端位姿、关节增量或夹爪状态。

## 2. 模型链路
视觉编码器把 RGB 或深度图转换成场景 token，语言编码器提供任务条件，状态编码器补充关节角、夹爪宽度和末端速度。融合模块可以采用 cross-attention、拼接投影或 token 交互，策略头再生成连续动作序列。真实部署通常采用 <font color='#2aa198'>receding horizon</font>：一次只执行短动作块，重新观测后再规划。

## 3. 数据组织
每条轨迹应同时保存 observation、action、timestamp、episode_id、task_id、camera_calibration 和 termination_reason。动作必须明确单位、坐标系、控制频率和是否相对上一帧。数据清洗不能只删除失败样本，因为碰撞前的恢复轨迹对于学习风险边界非常重要。

## 4. 训练阶段
第一阶段使用大规模多任务示范进行行为克隆，学习物体、工具和指令之间的对应关系；第二阶段用目标机器人数据做全量或 LoRA 微调；第三阶段加入失败恢复、人工纠正或离线强化学习。训练时应监控动作重建误差、验证成功率、长程任务完成率和动作平滑度。

## 5. 评测与消融
至少区分已见物体、未见物体、未见位置、未见指令表达和遮挡场景。报告成功率之外，还要报告平均完成步数、恢复次数、推理延迟、人工接管率和安全事件。消融实验应分别去掉语言条件、历史帧、状态输入和动作 chunking，确认提升来自哪里。

## 6. 实施清单
1. 标定相机内外参并固定图像尺寸、帧率和曝光策略。
2. 建立语言指令模板，覆盖同义表达、否定条件、数量和空间关系。
3. 统计每个任务的轨迹长度、成功率、失败原因和有效动作比例。
4. 分离训练、验证、未见物体和未见位置，避免同一场景泄漏。
5. 记录模型、数据、随机种子、硬件和推理配置版本。
