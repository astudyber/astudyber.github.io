# 1. 数据处理：从记录到可靠的训练样本

## 1.1 概览

本篇围绕机器人轨迹的数据链路展开：划分、同步、坐标、清洗、归一化、动作块与抽样验证。下面的流程是通用工程建议；具体字段和算法参数应由目标模型的数据接口决定。资料核对日期：2026-09-21。

![轨迹处理流程：保留原始记录，分组划分，对齐与清洗，仅用训练集拟合统计量，构造动作块](/data-pipeline.png)

图为 AI 辅助教学示意。关键顺序是先确定数据边界和评测划分，再拟合统计量；图中的未来动作是训练标签，不能泄漏为部署时不存在的输入。

# 2. 先定义划分，再处理数据

## 2.1 为什么不能随机按帧切分

相邻视频帧高度相似。如果同一抓杯过程的前半段进入训练集、后半段进入测试集，模型可能已经见过同一背景、物体和运动过程，评测结果会过于乐观。

建议至少按 episode 分组；若要测试跨场景泛化，则按场景划分。跨物体、跨操作者和跨机器人评测对应不同分组轴，不能只用一个随机种子解决所有泄漏问题。

## 2.2 保存原始数据

保留原始文件，清洗结果通过索引或新版本表达。记录被排除片段、规则版本和原因。若同一条轨迹被转码或裁剪成多个文件，仍保留相同的来源标识，便于去重与分组。

# 3. 时间对齐与坐标对齐

## 3.1 先对时，再采样

相机曝光、驱动收到帧、主机处理完成、动作命令发出，是四个不同事件。只使用“文件写入时间”可能错过真实先后关系。

一个可检查的对齐流程是：确定参考时钟 → 估计各传感器偏移 → 选择参考时间轴 → 按信号类型重采样 → 保存匹配误差 → 可视化回放。关节信号可以按需要插值，离散夹爪事件则不宜被线性插成不存在的中间状态。

## 3.2 动作频率改变时发生什么

绝对位置目标、速度命令、单步位移增量的降采样规则不同。把 50 Hz 的单步位移直接放到 10 Hz 执行，若不重新构造时间区间，轨迹速度就会改变。重采样时应结合原始控制语义，而不是统一“每隔五帧取一帧”。

## 3.3 变换链要有方向

设 $T_{B\leftarrow C}$ 表示把相机坐标转换到机器人基座坐标，则齐次点满足 $p_B=T_{B\leftarrow C}p_C$。记录外参时同时写明映射方向与单位。

平移点、速度向量和位姿增量的变换不完全相同。旋转数据还需要核对四元数顺序、归一化以及插值方式。相关坐标与单位约定可参考 [ROS REP-103](https://www.ros.org/reps/rep-0103.html)。

# 4. 清洗：错误记录与失败经验分开

| 数据现象 | 推荐处理 | 原因 |
| --- | --- | --- |
| 无法解码、关键字段缺失 | 隔离并记录 | 不存在可靠监督 |
| 时间严重错位 | 修正或隔离 | 图像与动作不对应 |
| 任务失败但记录完整 | 保留失败标签 | 可用于价值学习或恢复分析 |
| 人工接管 | 保存区间和控制来源 | 区分策略命令与实际执行 |
| 长时间等待 | 按任务语义判断 | 等待可能是必要行为 |
| 极端动作值 | 对照原始日志复核 | 可能是真实动作，也可能单位错误 |

<font color='#d33682'>失败轨迹不等于坏数据。</font>但把失败动作无条件作为行为克隆的正例，同样会教会错误行为。数据是否保留与如何进入损失函数，是两个独立决定。

# 5. 归一化与数据增强

## 5.1 只在训练集拟合统计量

标准化的教学表达为 $\tilde{x}=(x-\mu_{\mathrm{train}})/(\sigma_{\mathrm{train}}+\epsilon)$。验证、测试与部署必须使用同一组训练统计量。常量维度、异常范围以及夹爪离散值应有专门规则。

如果不同机器人的动作物理意义不同，应先统一语义或按本体处理，再讨论共享统计量。训练保存的反归一化参数必须跟随模型一起部署。

## 5.2 增强要保持任务标签成立

- 颜色变化：不能把“拿红杯子”增强成蓝色杯子，却保留原指令。
- 图像裁剪：检查目标仍可见；依赖相机内参的模型需同步更新内参。
- 几何翻转：左右方向和动作坐标可能同时改变，不能只翻图片。
- 时序增强：改变播放速度必须同步考虑动作频率与控制语义。
- 语言改写：保留数量、否定、顺序和空间关系。

# 6. 构造动作块

## 6.1 输入与标签

输入是部署时实际可取得的当前和历史信息，标签是未来命令。假设观察窗口为 $L$、动作块为 $H$，可写成 $X_t=(o_{t-L+1},\ldots,o_t)$ 与 $Y_t=(a_t,\ldots,a_{t+H-1})$。

边界填充配合掩码；不得跨 episode 取未来动作。下面只演示尾部有效性，不是完整数据加载器：

```python
def action_chunk(actions, start, horizon):
    valid = actions[start:start + horizon]
    mask = [True] * len(valid)
    missing = horizon - len(valid)
    padded = list(valid) + [None] * missing
    mask += [False] * missing
    return padded, mask
```

实际训练将 None 转为指定形状的填充值，并通过 mask 排除损失。若采用时间偏移读取，需要核对索引单位是帧还是秒；相关概念见 [LeRobotDataset 文档](https://huggingface.co/docs/lerobot/lerobot-dataset-v3)。

## 6.2 数据采样与多样性

按帧均匀采样会偏向长轨迹；按 episode 均匀采样又可能改变任务频率。建议同时报告每个任务的轨迹数、有效时长和采样概率。增加样本量时还应检查是否只是重复同一场景。

# 7. 交付一份可追溯的数据版本

应输出划分清单、处理配置、来源映射、异常报告、训练统计量和回放样本。最终检查三件事：训练与测试无同源泄漏；训练输入在部署时可用；动作反归一化后与原始命令一致。

实现参考：[RLDS](https://github.com/google-research/rlds)、[Open X-Embodiment](https://robotics-transformer-x.github.io/)。这些工具提供组织与转换基础，不会替代你对坐标、时间和标签语义的定义。


# 扩展图解：接口、机制与实验

## 1. 异步传感器对齐

![异步传感器对齐](/pipeline-sync.png)

训练用观测应模拟部署时可获得的信息。对控制时刻 t，可选择最近且不晚于 t 的相机帧，并限制最大时差；双向插值可能使用未来信息，是否允许取决于任务定义。

图中的缺帧区间应显式标记，不能无限沿用旧图像。对齐后统计时差分布，并抽样回放高速运动与接触阶段，因为这些位置最容易暴露同步错误。

## 2. 分组划分与重复检测

![分组划分与重复检测](/pipeline-split.png)

连续轨迹中的相邻帧高度相关，随机按帧划分会严重高估泛化。应根据问题选择按 episode、操作者、场景或物体分组，再检测跨集合近重复。

图中“同一组只进一侧”是基本约束，但不同组之间仍可能有同一物体和背景。若目标是新物体泛化，划分单位就必须包含物体身份，而不仅是录制日期。

## 3. 归一化与可逆变换

![归一化与可逆变换](/pipeline-normalize.png)

图示省略了零方差保护；实现应使用 max(σ, ε)，并在逆变换中使用同一尺度。末端位置用米，姿态另按旋转表示约定，不能把整个位姿都视为米。

归一化统计只在训练划分上拟合，验证与部署复用。对动作做 $z=(a-\mu)/(\sigma+\epsilon)$ 后，部署必须执行一致的逆变换，并保留单位与字段顺序。

图中反归一化是控制链的一部分。夹爪离散状态、角度周期性和极小方差维度需要专门处理；不能把全部字段盲目标准化后就假定语义完整保留。

## 4. 质量筛选与覆盖度

![质量筛选与覆盖度](/pipeline-quality.png)

这里的“删除”指从本次训练输入中过滤，并保留原始数据和原因记录。缺少任务标签的数据仍可能用于自监督学习；失败结果与数据损坏也应分别标注。

数据质量不等于全部成功。失败轨迹中可能包含恢复、接管和边界行为；是否保留取决于学习目标与标注。损坏传感器、错误单位和不可解释命令应与任务失败区分。

图中只保留常见成功会缩窄覆盖。建议把有效性、任务结果、难度和人工干预分别标注，再按用途构建训练视图；这样既能训练模仿策略，也能支持后续价值学习和错误分析。
