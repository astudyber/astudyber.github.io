# 2. GigaBrain-0：世界模型增强 VLA

## 2.1 概览与创新点

GigaBrain-0 利用世界模型生成数据，缓解真机示范收集昂贵的问题。论文还研究 RGBD 输入和具身中间监督，以增强空间与任务理解。应区分论文完整方案与公开权重支持的功能。参见 [GigaBrain-0 论文](https://arxiv.org/abs/2510.19430)。

## 2.2 数据引擎怎么理解

以下是理解合成数据价值的通用流程：

1. 从真实轨迹获得可信的物体、动作与交互关系。
2. 用生成模型扩展视觉条件或场景变化。
3. 检查目标物体是否保持身份、接触是否连贯、动作标签是否仍成立。
4. 将通过检查的合成样本与真实数据混合训练。
5. 在从未参与生成或筛选的真实场景上测试。

核心难点是第三步。若只替换外观而不改变几何，原动作标签可能仍有意义；若生成结果移动了杯子，却仍使用原来的抓取位置，就构成了错误监督。

## 2.3 公开实现的边界

官方仓库说明，初始公开权重为了易用性不包含深度图和中间 2D 操作轨迹输入，虽然代码提供相关配置能力。复现论文时必须核对权重、数据与配置，不能只检查仓库名称。参见 [GigaBrain 官方仓库](https://github.com/open-gigaai/giga-brain-0)。

# 3. 从数据扩展到学习闭环

## 3.1 GigaBrain-0.5M⁎ 与 RAMP

GigaBrain-0.5M⁎ 研究基于世界模型的强化学习，提出 RAMP，将世界模型提供的未来信息与策略学习结合。它回答“预测能力如何帮助改进动作策略”，不同于仅用生成视频扩充数据集。参见 [GigaBrain-0.5M⁎ 技术报告](https://arxiv.org/abs/2602.12099)。

解读这类方法时应逐项找证据：未来预测作为输入、作为训练监督，还是作为交互环境？奖励从哪里来？真实轨迹与模型轨迹如何配比？模型预测出错时是否会污染策略更新？

## 3.2 GigaWorld-Policy：动作居中的 WAM

GigaWorld-Policy 联合学习视觉动态与动作，同时强调动作解码效率；视频生成可以不是每次推理都执行的必选项。参见 [GigaWorld-Policy 论文](https://arxiv.org/abs/2603.17240)。

GigaWorld-Policy-0.5 进一步研究混合训练和专家分工，以保留视觉动态监督的收益并减少动作推理的计算。它属于该路线的后续工作，不应与 GigaBrain-0.5M⁎ 混淆。参见 [GigaWorld-Policy-0.5 论文](https://arxiv.org/abs/2607.13960)。

# 4. 三种“使用世界模型”的差别

| 使用位置 | 学习时发生什么 | 部署时需要什么 | 要核验的风险 |
| --- | --- | --- | --- |
| 数据生成 | 扩充训练样本 | 可能只运行策略 | 合成画面与动作错配 |
| 条件或规划 | 提供未来目标或候选轨迹 | 可能还要运行预测模型 | 预测偏差和额外延迟 |
| 联合训练 | 未来预测与动作共同学习 | 可设计为仅动作解码 | 训练收益能否迁移到控制 |

这是一种阅读分类，不是对所有实现细节的断言。阅读具体论文时，把数据流和推理流分别画出来，通常比只看模型名称更容易理解。

# 5. 怎样设计有说服力的实验

## 5.1 合成数据是否真的有用

建议固定真实数据量、训练预算、任务划分及评测种子，只改变合成数据比例。设置真实数据基线、真实加合成、真实数据重复采样三组，以区分“样本多了”和“变化更丰富了”。

对生成内容检查：物体是否凭空消失、遮挡关系是否一致、抓取后是否跟随夹爪移动、反光与阴影是否掩盖接触错误。视觉好看只是必要检查的一部分。

## 5.2 评测表应该包含什么

- 泛化轴：新物体、新位置、新背景、新相机分别报告。
- 长任务：逐阶段成功率，以及最终完成率。
- 效率：完整观察到动作的时延，是否包含视频生成。
- 恢复：失败后是否能继续，人工介入次数是多少。
- 复现信息：模型、代码、数据与标定版本。

论文中的收益只对应其具体实验设置。本笔记不把论文表格换算成其他平台的性能承诺，也不以演示视频代替统计评测。
