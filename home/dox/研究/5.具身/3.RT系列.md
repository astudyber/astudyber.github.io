# 1. RT 系列：把机器人动作写成 token

## 1.1 概览

<font color='#2aa198'>Robotics Transformer</font> 系列展示了从多任务机器人数据、互联网视觉语言知识到跨本体数据共享的不同扩展方向。本篇重点比较 RT-1、RT-2 和 RT-X，不把它们理解为简单增加层数的三个版本。资料核对日期：2026-09-21。

![RT 系列演进：RT-1 的动作 token、RT-2 的视觉语言联合训练、RT-X 的跨本体数据](/rt-evolution.png)

图为 AI 辅助教学示意。三行分别回答：怎样建模动作？怎样利用互联网知识？怎样共享不同机器人的经验？

# 2. RT-1：多任务机器人策略

## 2.1 概览与创新点

RT-1 用图像历史和语言指令预测离散动作。语言条件参与视觉编码，TokenLearner 压缩视觉 token，再由 Transformer 输出动作类别。它强调在真实机器人多任务数据上学习统一策略。参见 [RT-1 官方项目页](https://robotics-transformer1.github.io/)。

## 2.2 方法论

- 图像编码：将场景变为视觉特征；语言帮助模型关注与任务相关的区域。
- token 压缩：减少后续时序建模的输入长度。
- 时间建模：结合连续观测，而不是只把单张照片当分类题。
- 动作分类：预测各动作字段所属的离散区间。
- 反量化与执行：把类别映射回控制器使用的数值。

压缩视觉 token 和量化动作是两个不同步骤：前者减少输入计算，后者规定输出如何表示。

## 2.3 分箱的教学算例

假设一个动作维度允许范围为 $[-0.1,0.1]$ 米，使用 256 个等宽区间，则每格宽度约为 $0.2/256=0.00078125$ 米。预测类别后可取该区间中心作为控制目标。

这只解释量化，不代表整台机器人的空间误差只有 0.78 mm；标定、深度估计、执行器误差和延迟都可能更大。夹爪类别、终止信号与连续位移也不能未经定义就使用相同量化规则。

# 3. RT-2：从互联网语义到动作

## 3.1 概览

RT-2 把动作编码为可由视觉语言模型预测的 token，并联合训练视觉语言任务与机器人动作任务。其研究重点是把互联网预训练中的语义知识迁移到机器人控制。参见 [RT-2 论文](https://robotics-transformer2.github.io/assets/rt2.pdf)。

## 3.2 怎样理解知识迁移

例如，机器人可能已有抓取物体的运动技能，但机器人示范未覆盖“拿起那个灭绝的动物”这种表达。视觉语言知识有机会帮助它把指令指向恐龙玩具；真正抓取仍依赖已学会的运动能力和当前物理条件。

<font color='#d33682'>语义泛化不等于新运动技能凭空产生。</font>会识别螺丝刀，不代表已经学会控制接触力完成拧螺丝。

## 3.3 联合训练为何重要

互联网数据维持视觉语言理解，机器人数据建立“观测—动作”的对应关系。若只看语言损失，无法知道动作是否可执行；若只拟合窄任务示范，也可能损失原有语言能力。比较方法时应同时检查指令遵循与真实执行结果。

# 4. RT-X：跨本体的数据与迁移

## 4.1 概览

Open X-Embodiment 汇集多机构、多机器人的轨迹；RT-1-X、RT-2-X 用于研究混合本体训练能否产生正迁移。RT-X 既涉及数据组织，也涉及模型实验。参见 [Open X-Embodiment / RT-X 项目页](https://robotics-transformer-x.github.io/)。

## 4.2 统一格式之后还有哪些差异

| 差异 | 表面看起来 | 实际需要明确 |
| --- | --- | --- |
| 动作维度 | 都是一个浮点数组 | 关节目标或末端位移 |
| 坐标表示 | 都有 x、y、z | 基座坐标或工具坐标 |
| 采样频率 | 都是一段视频 | 动作间隔及保持时间 |
| 夹爪控制 | 都有一个数值 | 开合符号、宽度或力 |
| 成功标签 | 都标记完成 | 放稳、接触、到达或超时 |

本表是数据适配检查方法，不是 RT-X 的字段标准。跨本体学习要保留差异信息，而不是把不同语义强行拼成同一个数组。

# 5. 与 π 系列如何比较

| 路线 | 主要切入点 | 重点观察 |
| --- | --- | --- |
| RT-1 | 机器人多任务序列建模 | 动作离散化与数据覆盖 |
| RT-2 | 视觉语言知识迁移 | 新语义指令和组合任务 |
| RT-X | 多本体数据共享 | 混合数据是否帮助目标平台 |
| π0 | 连续动作块生成 | 精细动作和闭环控制 |
| π0-FAST | 压缩式动作分词 | token 数、重建误差与解码时延 |

后两行参见 [π0 方法介绍](https://www.pi.website/blog/pi0) 与 [FAST 官方说明](https://www.pi.website/research/fast)。这些是不同设计轴，不适合只按参数量排出统一优劣。

# 6. 可复现的评测设计

1. 固定已有物体和姿态，验证基础执行。
2. 固定运动任务，更换语言表述，测语义理解。
3. 保持任务目标，改变物体组合，测组合泛化。
4. 更换场景、相机或机器人时分别评测，避免混合多个变量。

每组记录成功次数 / 总次数、模型调用耗时、超时次数以及失败阶段。若模型选对了对象却抓不起来，应分别统计语义成功与动作成功。

推荐阅读顺序：RT-1 的输入输出 → RT-2 的联合训练 → RT-X 的数据标准化 → 与连续动作策略做同条件对照。


# 扩展图解：接口、机制与实验

## 1. 动作离散化的代价

![动作离散化的代价](/rt-tokens.png)

把连续动作映射为离散 token，便于复用序列建模工具，但引入量化误差。区间宽度为 Δ 时，使用区间中心重建的最大误差在未截断的均匀量化条件下为 Δ/2；超出范围的截断误差另算。

图中 token 是动作编码，不是直接让机器人执行自然语言。平移、旋转和夹爪字段的范围应分别定义；提高分辨率会扩大词表或增加序列长度，带来训练与解码成本。

## 2. 从语义知识到动作输出

![从语义知识到动作输出](/rt-semantic.png)

RT-2 的关键研究问题是把视觉语言知识转移到机器人动作预测。共享模型有机会利用物体关系和指令语义，但机器人动力学、接触约束和控制接口仍需动作数据与闭环验证。

图中的两类任务应保留各自监督语义。网页图文知识可以帮助识别“哪个物体适合盛水”，却不能直接保证抓取力、夹爪宽度和碰撞间隙正确。[RT-2 原文](https://robotics-transformer2.github.io/assets/rt2.pdf)。

## 3. 跨机器人数据混合

![跨机器人数据混合](/rt-mixture.png)

跨机器人训练的难点不只是文件格式。不同相机、动作空间、任务频率和示范质量共同影响梯度。统一字段后仍应保留本体标识、有效维度掩码与数据来源，以便分析负迁移。

图中的采样混合决定哪些任务获得训练权重。按原始步数混合可能让长轨迹或高频机器人占优；按任务、episode 或质量分层采样会改变优化目标，必须记录比例。[Open X-Embodiment](https://robotics-transformer-x.github.io/)。

## 4. 泛化评测的层次

![泛化评测的层次](/rt-eval.png)

泛化不是单一指标。新物体可能仍处于熟悉场景，新指令可能只是同义改写，新本体则同时改变观测与控制。应逐项控制变量，再测试组合变化。

图中每张评测卡都要对应独立的初始状态与明确成功条件。报告成功次数／总次数、超时规则和人工干预，避免把少量精选演示当作平均能力。训练数据是否含测试物体或近似任务，也应单独说明。
