# 1. GR00T：从视觉语言理解到连续动作

## 1.1 概览

<font color='#2aa198'>GR00T</font> 是 NVIDIA 的通用机器人研究路线。本篇以 N1 的双系统思路为起点，对照 N1.5、N1.6 和 N1.7 的公开说明；版本不同，骨干、动作头和适配方式也会变化。资料核对日期：2026-09-21。

> 阅读时始终追问三个问题：图像和指令如何进入模型？机器人状态如何参与决策？输出如何变成当前硬件能执行的动作？

![GR00T 概念图：视觉语言特征与状态、噪声共同生成连续动作块](/groot-architecture.png)

图为本笔记的 AI 辅助概念示意，不是某一版本的逐层网络结构。按箭头读：先编码语义，再结合本体状态生成动作，执行部分动作后重新观测。图中的 DiT 是动作生成网络，不能直接等同于电机控制器。

## 1.2 双系统的含义

N1 将视觉语言模型与动作生成模型组合：前者提取图像和指令的表征，后者生成连续控制序列。“System 2 / System 1”是架构解释，不意味着系统必须先输出一篇文字推理再移动机械臂。参见 [N1 官方架构介绍](https://developer.nvidia.com/blog/accelerate-generalist-humanoid-robot-development-with-nvidia-isaac-gr00t/)。

| 模块 | 接收什么 | 产生什么 | 需要核对的接口 |
| --- | --- | --- | --- |
| 视觉语言编码器 | 相机图像、任务描述 | 多模态特征 | 相机顺序、图像尺寸、语言模板 |
| 状态编码 | 关节、夹爪等状态 | 本体相关特征 | 维度、单位、字段顺序 |
| 动作模型 | 条件特征、状态、噪声动作 | 未来动作块 | 动作空间、预测长度 |
| 执行适配器 | 模型输出 | 控制器目标值 | 反归一化、限幅、控制模式 |

# 2. 版本演进

## 2.1 N1.5：改善条件融合与训练

N1.5 保留 Eagle VLM，DiT 通过交叉注意力读取视觉语言特征，处理状态与带噪动作。官方说明中 VLM 在预训练和微调时冻结，因此不能把“微调 GR00T”默认解释成所有参数都更新。参见 [N1.5 发布说明](https://research.nvidia.com/labs/gear/gr00t-n15/)。

## 2.2 N1.6：骨干、动作头与动作表示变化

N1.6 官方研究页介绍了 Cosmos-2B 系列内部 VLM、32 层 DiT，以及对多数本体采用相对当前状态的动作块。相对动作的参考状态必须写清楚：相对预测开始时的状态，与逐步相对上一目标累加，并不是同一种解码。参见 [N1.6 研究说明](https://research.nvidia.com/labs/gear/gr00t-n1_6/)。

## 2.3 N1.7：进一步引入推理能力

N1.7 的官方介绍采用 Cosmos-Reason2-2B，并继续围绕机器人理解、动作生成与部署优化展开。使用时应锁定相应代码标签和模型卡，不能将 N1.5 的数据配置直接视为 N1.7 的规范。参见 [N1.7 官方技术介绍](https://developer.nvidia.com/blog/develop-humanoid-robot-policies-end-to-end-with-nvidia-isaac-gr00t/)。

# 3. 方法论：怎样读懂一次动作生成

## 3.1 条件、噪声与动作块

以下是连续动作生成的教学抽象，而非特定版本源码：

- 条件 $c$：任务、图像、本体状态以及必要的机器人标识。
- 动作块 $A_t=[a_t,\ldots,a_{t+H-1}]$：未来 $H$ 步的目标动作。
- 生成过程：从噪声出发，在条件约束下逐渐得到动作块。
- 闭环执行：执行前 $K$ 步，再获取新观测，其中 $K \leq H$。

例如，假设预测 16 步、每步间隔 50 ms、只执行前 4 步：模型预测窗口为 0.8 s，重规划间隔约为 0.2 s。这是帮助理解的算例，不是 GR00T 的统一默认配置。推理与通信耗时还要计入实际周期。

## 3.2 跨本体不是补零就结束

两个机器人即使都有 7 维输出，也可能分别使用“6 维末端增量 + 夹爪”和“7 个关节目标角”。维度相同不代表语义一致。先定义字段，再决定投影、掩码、归一化及本体适配配置。

<font color='#d33682'>特别容易出错：</font>左右臂顺序互换、夹爪开合方向相反、关节角度与弧度混用、训练时采用绝对目标而部署时当成增量。

# 4. 数据与适配实验

## 4.1 一次最小实验

1. 选择一个可重复的桌面抓放任务，固定机器人、相机与控制模式。
2. 录制成功示范，也记录失败原因与人工接管区间。
3. 可视化叠加状态、命令、夹爪开合曲线，检查时间对应关系。
4. 先用少量轨迹验证模型能拟合，再扩大数据和物体变化。
5. 在独立初始状态上评测；进一步单独测试新物体、新背景和新指令。

“少量样本拟合成功”只能说明训练链路基本通畅，不能证明泛化。公开权重是否适合当前本体，也需以模型卡的支持范围为准。

## 4.2 失败定位表

| 现象 | 优先检查 | 建议对照实验 |
| --- | --- | --- |
| 看对物体却朝反方向移动 | 坐标系、动作符号 | 回放固定方向的小位移命令 |
| 靠近目标后振荡 | 延迟、增量累加、执行窗口 | 缩短执行窗口并记录实际时间 |
| 换语言后仍做原任务 | 指令标注、任务分布 | 固定画面，仅替换互斥指令 |
| 换相机后性能骤降 | 视角、裁剪、标定 | 保持其余条件固定做相机消融 |

# 5. 评测与阅读建议

每次记录模型版本、可训练模块、训练数据划分、动作表示、预测长度、执行长度、端到端延迟和任务成功次数。报告成功率时写明分母，并将超时、抓取失败和放置失败分开统计。

推荐阅读顺序：N1 架构 → 目标版本的变更说明 → 数据配置 → 本体适配与推理接口 → 真机评测。论文、模型卡、代码可能对应不同发布状态，应一起保存版本信息。

进一步资料：[GR00T N1 论文](https://arxiv.org/abs/2503.14734)、[NVIDIA GR00T 平台](https://developer.nvidia.com/isaac/gr00t)。
