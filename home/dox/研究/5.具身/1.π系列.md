# 1. Pi0：连续动作的流匹配模型

## 1.1 概览

《π0: A Vision-Language-Action Flow Model for General Robot Control》

<font color='#2aa198'>π0</font> 把预训练视觉语言模型与连续动作生成结合：图像和指令提供语义，本体状态描述机器人自身，动作专家输出未来一段控制序列。它研究通用机器人策略，既可以直接测试预训练能力，也可以用目标任务数据后训练。参见 [π0 官方介绍](https://www.pi.website/blog/pi0)。

资料核对日期：2026-09-21。本篇保留原有架构图和 FAST / BPE 学习图，新增路线总览，并补齐 π0.5、π0.6／π*0.6 和 π0.7。新增配图为 AI 辅助教学示意，不是官方实验结果图。

![π 系列路线总览：连续动作、压缩分词、开放世界泛化、经验学习和多种引导信号](/pi-overview.png)

按图从上到下阅读：π0 解决连续动作接口；FAST 研究动作表示；π0.5 扩展异构知识与长任务；π*0.6 利用经验改进；π0.7 强调多种上下文引导。它们的贡献不只是参数量递增。

## 1.2 创新点与输入输出

- 以预训练 VLM 提供视觉语言表征，连接机器人控制。
- 通过 Action Expert 和 flow matching 表示连续动作分布。
- 一次预测动作块，而不是每次只输出一个孤立动作。
- 利用多机器人、多任务数据，后续再适配具体任务。

原始 π0 使用 PaliGemma 骨干和较小的动作专家。图像、语言、本体状态与动作 token 的处理并不完全相同；不能把“所有输入拼起来”当成完整结构描述。参见 [π0 论文与架构附录](https://arxiv.org/html/2410.24164v1)。

## 1.3 方法论与读图

![原有 π0 架构学习图](/image-20260916193446738.png)

读图时区分三组变量：

| 符号 | 本篇含义 | 容易混淆之处 |
| --- | --- | --- |
| $o_t$ | 图像与本体状态等观测 | 不只是单张图片 |
| $q_t$ | 当前机器人本体状态 | 不等同于所有视觉观测 |
| $A_t$ | 从当前时刻起的动作块 | 不是已经执行的轨迹 |
| $\tau$ | 生成过程中的流时间 | 不是机器人真实时间 $t$ |

视觉与语言由 VLM 提供表征，状态与带噪动作进入动作专家；注意力掩码约束不同 token 之间的信息访问。条件特征可在生成过程中复用，但具体 KV 缓存方式应以实现为准，不能只凭示意图推断所有模块的计算流程。

## 1.4 用一个公式理解 flow matching

下面采用“噪声到数据”的教学约定，方便理解；论文或代码也可能采用反向时间参数化。

设真实动作块为 $A$，高斯噪声为 $\epsilon$，插值为 $x_\tau=(1-\tau)\epsilon+\tau A$。沿该直线路径的目标速度为 $A-\epsilon$，模型学习在观测条件下预测相应的速度场。

训练时可以抽取某个 $\tau$ 计算学习目标；推理时从噪声出发，数值积分得到动作块。因此，“一次生成完整动作块”不等于“网络只做一次前向”。

动作块内部可以同时包含多关节和夹爪命令。DoF 是自由度，但状态向量、动作向量和机器人的物理自由度不一定数值相同。

## 1.5 模型训练与闭环执行

预训练强调多样化任务和本体覆盖，后训练强调目标应用中的高质量行为。视觉语言预训练提供语义先验，机器人轨迹提供动作监督，二者的来源与用途需要区分。

教学算例：在 50 Hz 的控制频率下，50 步动作覆盖 1 s。策略可只执行前 10 步，再获取新图像重规划；是否能每 0.2 s 更新，还取决于模型、相机和通信总延迟。这些数值是算例，不代表统一部署配置。

评测应记录预测长度、执行长度、推理采样步数及端到端时延。不能把某台 GPU 上的单次模型耗时直接解释为所有机器人的控制频率。

# 2. Pi0-FAST：压缩动作，而不是逐维分箱

## 2.1 概览

《FAST: Efficient Action Tokenization for Vision-Language-Action Models》

FAST 是动作分词方法；π0-FAST 是采用该动作表示的自回归 VLA。它利用动作在时间上的结构，把一段连续轨迹转换为更紧凑的离散 token。参见 [FAST 论文](https://arxiv.org/html/2501.09747v1)。

## 2.2 为什么简单分箱不够

假设一个动作块有 50 步、每步 7 维，逐维逐步编码就有 350 个数值位置。平滑动作中相邻数值高度相关，却仍占据大量输出位置。压缩的目标是保留对控制重要的信息，同时减少冗余。

![原有动作分箱与表示学习图](/image-20260916202432037.png)

![原有频域动作表示学习图](/image-20260916202547771.png)

Transformer 本身可以连接回归头预测连续值；“必须离散化”针对的是使用离散词表、next-token prediction 的这条建模路线，不是 Transformer 的数学限制。

## 2.3 FAST 的处理步骤

![原有 FAST 手写流程参考图](/ChatGPT Image 2026年9月16日 20_44_20.png)

按图理解流程：归一化 → 沿时间维做 DCT → 量化系数 → 按约定顺序展平 → BPE 编码。解码按逆向恢复，最后反归一化得到控制数值。

**原图校注：**“350 个数”“约 40 个整数”“30～60 个 token”用于帮助理解，不能当作所有动作块的固定大小；DCT 本身不减少系数总数。量化会让许多小系数变为零，之后再通过编码压缩。图中“截断高频”不能理解成 FAST 必然把全部高频直接删掉，具体以 tokenizer 实现为准。

DCT 可理解为将时间序列分解为余弦基的组合：低频描述较缓慢的整体变化，高频描述较快变化。关键接触动作也可能包含有用高频成分，因此压缩程度需要结合重建误差与任务表现检查。

## 2.4 BPE 的编码与解码

![原有 BPE 手写讲解图](/ChatGPT Image 2026年9月16日 20_50_10.png)

图中的小例子把常见相邻对逐次合并：先把 1、2 合为一个新符号，再把这个符号与 3 合并。实际 BPE 在训练语料上学习合并规则；对新序列编码时使用已经固定的规则，而不是临时为每条轨迹重新建立词表。

BPE 的符号合并可以逆转；连续动作信息的近似误差主要来自量化等处理。token 更少不自动等于控制更准，仍需比较反解动作与原动作的差异。

## 2.5 训练提速不等于推理更快

FAST 官方报告的最高约 5 倍是特定实验中的训练提速。官方也指出，π0-FAST 的自回归解码相较 π0 的流匹配解码更慢。因此不能把原笔记里的“推理更快”作为普遍结论。参见 [FAST 官方说明](https://www.pi.website/research/fast)。

比较时同时记录：训练预算、每块 token 数、解码时延、重建误差与任务成功率。FAST、FAST+ 和采用它们的策略模型也应分别标明。

# 3. Pi0.5：开放世界泛化

## 3.1 概览

《π0.5: a Vision-Language-Action Model with Open-World Generalization》

π0.5 在 π0 路线上研究异构任务联合训练，结合机器人动作、视觉语言信息和语义子任务等监督，面向未见家庭环境中的长程操作。它的论文名称不同于 π0，不能沿用原笔记中重复的标题。参见 [π0.5 论文](https://arxiv.org/html/2504.16054v1)。

## 3.2 创新点

- 利用来源与监督类型不同的数据，扩展知识覆盖。
- 将高层语义子任务与低层动作联系起来。
- 关注新环境中的任务执行，而不仅是训练桌面的重复抓取。
- 通过联合训练研究不同层级知识如何帮助泛化。

“异构”不只是多放几个数据集，而是样本可能分别监督问答、定位、语言子任务或连续动作。每个样本应该计算哪些损失，需要与训练配方对应。

## 3.3 方法与读图

![原有 π0.5 异构训练与分层动作学习图](/image-20260917103519572.png)

以“整理厨房”为教学例子：先根据当前场景选择“拿起盘子”，再生成实现该子任务的动作；盘子放好后重新判断下一件事。高层给出语义方向，低层处理连续运动，二者都要根据真实进展更新。

如果高层选择错误目标，低层抓取再精确也无法完成总任务；如果高层正确而抓取失败，也不能立即切换到下一子任务。评测时应区分两类错误。

## 3.4 泛化需要怎样验证

分别测试新物体、新布局、新房间和新任务组合。只改变背景图案，与进入完全未见家庭，并非相同难度。官方演示和评测范围见 [π0.5 发布说明](https://www.pi.website/blog/pi05)。

# 4. Pi0.6 与 Pi*0.6：从经验中学习

## 4.1 概览与命名

《π*0.6: a VLA that Learns from Experience》

π0.6 是基座模型；π*0.6 是应用 RECAP 的强化学习模型。RECAP 的名称对应 RL with Experience & Corrections via Advantage-conditioned Policies，强调示范、纠正和自主经验的结合。参见 [官方研究说明](https://www.pi.website/blog/pistar06)。

## 4.2 为什么只模仿示范还不够

机器人一次抓偏会改变后续状态，而示范数据未必包含这种局面。继续运行时，小错误可能累积成大失败。补充“策略自己会遇到的状态”比单纯增加顺利示范更有针对性。

![经验学习的通用教学闭环：示范、策略执行、价值估计与更新](/rl-loop.png)

本图是强化学习的通用概念流程，不是 RECAP 的完整实现。π*0.6 的具体训练阶段、价值目标和条件表示应以报告为准。

## 4.3 RECAP 的核心思路

先让机器人有基本行为，再采集自主运行和专家纠正；根据任务结果学习价值，给动作提供优势条件，训练策略区分行为质量。执行时使用期望的高优势条件引导行为。

它并不是“失败的轨迹全部丢掉”。失败片段能帮助识别错误状态，专家接管则提供恢复方向；关键在于相应标签与训练目标。

## 4.4 评测看成功率，也看吞吐量

任务是否完成与完成得多快都重要。把机器人每次都慢慢挪到成功，与长时间稳定高效工作区分开来。还应记录接管次数、恢复表现和完整运行时长，避免只选择成功片段。

# 5. Pi0.7：可引导的通用策略

## 5.1 概览

《π0.7: a Steerable Generalist Robotic Foundation Model with Emergent Capabilities》

π0.7 研究如何通过多种上下文描述“做什么”和“怎样做”，支持语言、执行质量或速度元数据、控制模态及视觉子目标等信息。参见 [π0.7 官方介绍](https://www.pi.website/blog/pi07) 与 [论文](https://arxiv.org/abs/2604.15483)。

## 5.2 引导信号分别解决什么

| 条件 | 教学例子 | 减少的歧义 |
| --- | --- | --- |
| 任务与子步骤语言 | 把杯子放入托盘 | 当前目标 |
| 质量或速度信息 | 区分不同执行质量的轨迹 | 数据中的行为偏好 |
| 控制模态 | 关节目标或末端控制 | 动作的解释方式 |
| 视觉子目标 | 托盘中杯子的目标摆放 | 空间结果 |

表中的例子用于解释条件含义，不是保证模型接受这些原样字符串的 API。使用公开实现时仍需核对输入协议。

## 5.3 为什么有助于使用不同质量的数据

同一任务可能有不同路径、速度和执行质量。给数据增加条件，可以帮助模型区分这些行为，而不是把相互矛盾的动作平均到一起。视觉子目标也能描述文字不容易明确表达的空间布局。

新任务组合的表现应由明确划分验证，不能仅凭能听懂新句子就判定获得了任意技能。世界模型生成的目标画面也要检查可达性与物理一致性。

# 7. 复现中的三个关键推导

## 7.1 Flow Matching 学习的对象

采用一条教学用线性插值路径 $x_t=(1-t)x_0+tx_1$，其中 $x_0$ 是噪声，$x_1$ 是真实动作块，则路径速度为 $x_1-x_0$。模型学习条件速度场 $v_\theta(x_t,t,c)$，可以用平方误差拟合目标速度。推理从噪声出发，数值积分到动作端。

这里 t 是生成过程的时间，不是机器人的真实控制时刻。不同实现可能反向定义时间、采用不同路径或噪声约定，读取源码时要一起核对采样端点和积分方向。[π0 论文](https://arxiv.org/abs/2410.24164)。

## 7.2 FAST 的压缩不等于免费加速

DCT 将动作随时间的变化映射到频域；完整变换本身可逆，并不会凭空减少维度。实际压缩还依赖量化与后续编码，高频细节的保留影响动作精度。BPE 的合并规则从训练语料学习，不能在每条轨迹上任意改变后还期待 token 具有一致意义。

训练序列变短可以减少一部分计算，但自回归生成仍有串行依赖；连续动作生成的积分步数与 token 解码步数也不是同一种成本。比较 FAST 与连续动作头时，应同时测任务成功率、动作误差和端到端闭环延迟。[FAST 论文](https://arxiv.org/abs/2501.09747)。

## 7.3 从离线损失到闭环性能

动作均方误差小，可能只是模型接近平均示范；真实执行时的小偏差会改变下一观测，策略随后面对训练较少覆盖的状态。因此离线预测指标不能代替闭环成功率。

建议建立四组对照：相同数据不同动作表示；相同表示不同预测长度；相同模型不同执行窗口；相同策略不同延迟。每组固定其他条件，记录失败阶段和恢复次数。模型版本、数据统计、动作接口和执行调度共同决定结果，不能只凭“用了 π 模型”解释性能。
