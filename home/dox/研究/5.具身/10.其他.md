# 1. 其他具身主题：把各模块连成可验证的系统

## 1.1 概览

# 2. 任务规划与技能选择

## 2.1 语言计划怎样落地

“收拾桌子”可以分解为识别垃圾、收纳餐具、擦拭桌面等阶段。但每个阶段必须对应可执行技能，并有前置条件和完成判据。

SayCan 通过语言相关性与技能可行性结合来选择行动，为“说得合理”与“当前做得到”建立联系。参见 [SayCan 项目页](https://say-can.github.io/)。

## 2.2 一个教学技能契约

以“把杯子放到托盘”为例：

| 项目 | 内容 |
| --- | --- |
| 前置条件 | 杯子可见且可达，托盘区域明确 |
| 输入 | 目标实例、目标区域、当前状态 |
| 执行 | 接近、抓取、移动、松开 |
| 完成判据 | 杯子位于托盘且稳定，夹爪已释放 |
| 失败判据 | 目标丢失、杯子掉落、执行超时 |
| 恢复入口 | 重新定位或重抓 |

计划层只输出“抓杯子”却没有实例标识，会在多个相似杯子场景中产生歧义。结构化接口可以明确目标与约束，但接口本身不保证感知正确。

# 3. 视觉、触觉与接触

## 3.1 不同传感器回答不同问题

视觉适合获取物体类别、空间布局和大范围状态；触觉或力反馈有助于识别接触、滑移和抓持状态。遮挡最严重的时刻，往往正是精细操作最需要反馈的时刻。

“夹爪看起来已经闭合”和“确实夹住物体”不是同一个判断。可结合夹爪宽度、电流、力或触觉信号，但信号含义取决于具体设备。

## 3.2 融合的第一步仍是对齐

先统一时间和坐标，再比较早期特征融合、后期决策融合或不同频率的分层处理。新增模态若同步错误，反而可能比只用视觉更差。实验要有单模态基线，并明确缺失或失效传感器时的处理方式。

# 4. 记忆与长程任务

## 4.1 记住什么

长期任务中的记忆可以分为：已经完成的子任务、目标曾出现的位置、最近失败原因，以及当前任务约束。把所有历史视频塞进模型，不一定比维护结构化事件更有效。

例如“柜门已经打开”是可失效的状态：被人关上后，系统必须接受新观测而不是继续信任旧记忆。记忆应包含时间和证据，允许更新。

## 4.2 误差如何累积

教学算例：若 10 个阶段独立且每阶段成功概率均为 0.95，整项任务一次成功概率约为 $0.95^{10}\approx0.60$。真实阶段往往并不独立，但这个算例说明仅报告单步技能成功率会掩盖长任务难度。

恢复机制可能比继续提升已经很高的单步分数更重要。应单独记录失败后的重试是否有效，而不是只展示顺利完成的视频。

# 5. 开放词汇与空间定位

知道“杯子”是什么，不等于知道用户指的是哪一个，更不等于知道可抓区域。把任务拆成类别识别、实例选择、空间定位和动作生成，能帮助设计互相独立的测试。

语言中“左边”需要参考系，“空杯子”需要观察内部状态，“那个”需要对话或指点上下文。无法确定时，系统需要可表达的歧义状态，而不是把随机选择解释为推理。

# 6. 多机器人协作

多机器人任务增加了资源和通信约束：谁负责目标、谁占用共享通道、谁确认交接成功。任务分配与单机运动控制仍是不同层次。

建议记录任务所有权、时间戳与交接状态，并在通信延迟和单机失败时测试重新分配。两个机器人各自策略成功，不代表同时运行时不会互相阻挡。

# 7. 数据、评测与研究复现

## 7.1 结果表的最小信息

| 维度 | 建议记录 |
| --- | --- |
| 数据 | 来源、授权范围、场景与任务划分 |
| 模型 | 代码版本、权重、训练设置 |
| 系统 | 本体、相机、控制模式、计算设备 |
| 任务 | 初始条件、成功定义、超时规则 |
| 结果 | 成功次数 / 总次数、耗时、接管、失败类型 |

家庭环境数据可能含人脸、声音和私人空间，采集与分享时应保存授权范围，并尽量减少与任务无关的信息。本项是数据管理原则，不作为具体法律判断。

## 7.2 三个可开始的小课题

- 失败恢复：固定基础抓取模型，只增加恢复示范，比较接管次数是否下降。
- 记忆有效性：对有遮挡的长任务比较无记忆、事件记忆和图像历史。
- 触觉增益：保持视觉数据不变，单独测试接触阶段加入触觉后的收益。

每个课题都应固定其他变量、明确成功条件，并保留失败回放。

模型路线先读 π、GR00T 与 RT；预测和数据引擎读极佳视界与 WAM；工程实践依次读数据格式、数据处理、仿真和强化框架。最后回到本篇，把各模块放进同一任务链路。
